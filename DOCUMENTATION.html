1. 🎯 Visão Geral

Este projeto implementa a infraestrutura completa para o sistema BIA usando Terraform na AWS, com suporte a múltiplos ambientes e CI/CD automatizado.

Componentes Principais:

  • ECS Cluster - Orquestração de containers
  • Application Load Balancer - Distribuição de tráfego
  • RDS PostgreSQL - Banco de dados
  • VPC - Rede isolada
  • Auto Scaling - Escalabilidade automática
  • CloudWatch - Monitoramento e logs

3. 🔐 Gerenciamento de Secrets

✅ Implementado: Nomenclatura padronizada e estrutura unificada dos secrets.

Nomenclatura Padronizada:

Ambiente Nome do Secret Descrição Localização
Desenvolvimento bia-dev-secrets Credenciais completas do banco para dev AWS Secrets Manager
Produção bia-prod-secrets Credenciais completas do banco para prod AWS Secrets Manager

Estrutura do Secret:

{
  "username": "postgres",
  "password": "generated_password",
  "engine": "postgres",
  "host": "hostname_only",
  "port": 5432,
  "dbname": "bia"
}
Importante: O campo "host" contém apenas o hostname do RDS, sem a porta. A porta é armazenada separadamente no campo "port".

Configuração de Secrets:

# Configurar secrets para desenvolvimento
./setup-secrets.sh dev

# Configurar secrets para produção
./setup-secrets.sh prod

Validação Manual:

# Verificar secret do dev
aws secretsmanager get-secret-value --secret-id bia-dev-secrets

# Verificar secret do prod
aws secretsmanager get-secret-value --secret-id bia-prod-secrets

4. ⚡ Auto Scaling

⚠️ Importante: O auto scaling está separado em dois níveis independentes.

4.1 Auto Scaling de Tasks ECS

Localização: modules/ecs-service/main.tf

Parâmetro DEV PROD Configuração
Min Tasks 1 1 task_min_capacity
Max Tasks 10 10 task_max_capacity
Desired Tasks 1 1 task_desired_capacity
CPU Target 70% 70% cpu_scale_target
Scale Out Cooldown 300s 300s cpu_scale_out_cooldown
Scale In Cooldown 600s 600s cpu_scale_in_cooldown

Como Alterar:

Edite o arquivo locals.tf:

env_config = {
  dev = {
    # ECS Tasks Auto Scaling
    task_min_capacity         = 1      # Mínimo de tasks
    task_max_capacity         = 10     # Máximo de tasks
    task_desired_capacity     = 1      # Tasks iniciais
    cpu_scale_target          = 70.0   # % CPU para escalar
    cpu_scale_out_cooldown    = 300    # Cooldown scale out (segundos)
    cpu_scale_in_cooldown     = 600    # Cooldown scale in (segundos)
  }
}

4.2 Auto Scaling de Instâncias EC2

Localização: modules/ecs-cluster/main.tf

Parâmetro DEV PROD Configuração
Min Instances 1 1 instance_min_capacity
Max Instances 4 4 instance_max_capacity
Desired Instances 1 1 instance_desired_capacity
Scale Up Threshold 70% 70% CloudWatch Alarm
Scale Down Threshold 30% 30% CloudWatch Alarm

Como Alterar:

Edite o arquivo locals.tf:

env_config = {
  dev = {
    # EC2 Instances Auto Scaling
    instance_min_capacity     = 1      # Mínimo de instâncias
    instance_max_capacity     = 4      # Máximo de instâncias
    instance_desired_capacity = 1      # Instâncias iniciais
  }
}

Para alterar os thresholds de CPU, edite modules/ecs-cluster/main.tf:

# CloudWatch Alarm para Scale Up
resource "aws_cloudwatch_metric_alarm" "cpu_high" {
  threshold = "70"  # Altere aqui o threshold para scale up
}

# CloudWatch Alarm para Scale Down
resource "aws_cloudwatch_metric_alarm" "cpu_low" {
  threshold = "30"  # Altere aqui o threshold para scale down
}

5. 🗄️ Banco de Dados

Configurações Atuais:

Parâmetro DEV PROD Localização
Engine PostgreSQL 17.4 PostgreSQL 17.4 modules/rds/main.tf
Instance Class db.t3.micro db.t3.micro locals.tf
Multi-AZ false false modules/rds/main.tf
Backup Retention 1 dia 7 dias locals.tf
Storage 20 GB 20 GB modules/rds/variables.tf

Como Alterar Configurações do RDS:

1. Alterar Instance Class:

Edite locals.tf:

env_config = {
  dev = {
    rds_instance_class = "db.t3.micro"    # ou db.t3.small, db.t3.medium
  }
  prod = {
    rds_instance_class = "db.t3.small"    # Maior para produção
  }
}

2. Alterar Backup Retention:

Edite locals.tf:

env_config = {
  dev = {
    backup_retention_period = 1     # Dias de backup
  }
  prod = {
    backup_retention_period = 14    # Mais dias para produção
  }
}

3. Habilitar Multi-AZ:

Edite locals.tf:

env_config = {
  prod = {
    multi_az = true    # Habilita Multi-AZ para produção
  }
}

4. Alterar Credenciais do Banco:

Edite variables.tf:

variable "environment_variables" {
  default = [
    {
      name  = "DB_PWD"
      value = "nova_senha"    # Altere aqui
    },
    {
      name  = "DB_HOST"
      value = "novo_host"     # Altere aqui
    },
    {
      name  = "DB_USER"
      value = "novo_usuario"  # Altere aqui
    }
  ]
}

7. 🌐 Rede

Configurações de Rede por Ambiente:

Parâmetro DEV PROD
VPC CIDR 172.16.48.0/20 172.16.0.0/20
ECS Subnets Públicas Privadas
NAT Gateway Não Sim
Public IP Sim Não

Como Alterar Configurações de Rede:

1. Alterar CIDR da VPC:

Edite modules/vpc/main.tf:

resource "aws_vpc" "main" {
  cidr_block = var.environment == "dev" ? "10.0.0.0/16" : "10.1.0.0/16"
}

2. Habilitar/Desabilitar NAT Gateway:

Edite locals.tf:

env_config = {
  dev = {
    create_nat_gateway = false    # Desabilitado para economia
  }
  prod = {
    create_nat_gateway = true     # Habilitado para segurança
  }
}

3. Alterar Tipo de Subnets para ECS:

Edite locals.tf:

env_config = {
  dev = {
    use_private_subnets = false   # ECS em subnets públicas
  }
  prod = {
    use_private_subnets = true    # ECS em subnets privadas
  }
}

9. 🔧 Troubleshooting

Problemas Comuns:

1. Deploy Falha por Falta de Recursos

Erro: "InsufficientCapacity" ou "ResourcesNotAvailable"
Solução: Aumentar o número máximo de instâncias ou alterar o tipo de instância.

2. Tasks não Conseguem se Conectar ao RDS

Erro: Connection timeout para o banco
Solução: Verificar security groups e configurações de rede.

3. Auto Scaling não Funciona

Erro: Tasks não escalam automaticamente
Solução: Verificar métricas do CloudWatch e configurações de threshold.

4. Problemas com Secrets do Banco

Erro: Aplicação não consegue conectar ao banco
Solução: Verificar se o secret existe e tem a estrutura correta: 
# Verificar secret
aws secretsmanager get-secret-value --secret-id bia-dev-secrets

# Recriar se necessário
./setup-secrets.sh dev

5. Serviço ECS não Atualizado

Erro: Mudanças nos secrets não refletem na aplicação
Solução: Forçar nova implantação do serviço: 
aws ecs update-service --cluster bia-dev-cluster --service bia-dev-service --force-new-deployment

6. Workflow GitHub Actions Falha

Erro: Authentication failed
Solução: Verificar se os secrets AWS estão configurados corretamente.

Comandos Úteis:

# Verificar estado do Terraform
terraform show

# Listar recursos
terraform state list

# Ver outputs
terraform output

# Validar configuração
terraform validate

# Planejar mudanças
terraform plan -var="environment=dev"

# Aplicar mudanças
terraform apply -var="environment=dev"

# Destruir recursos
terraform destroy -var="environment=dev"
