📋 Visão Geral do Projeto

O que é o Projeto BIA?

O projeto BIA é uma infraestrutura completa na AWS para hospedar uma aplicação containerizada usando ECS (Elastic Container Service). A infraestrutura é gerenciada através do HCP Terraform Cloud e inclui todos os componentes necessários para um ambiente de produção robusto.

🎯 Objetivo: Fornecer uma infraestrutura escalável, segura e de alta disponibilidade para a aplicação BIA.

Características Principais

  • Gerenciamento via HCP Terraform Cloud - Deploy automatizado e controle de estado
  • Arquitetura Multi-AZ - Alta disponibilidade em múltiplas zonas
  • Auto Scaling - Escalabilidade automática baseada em métricas
  • Segurança Avançada - WAF, Security Groups, IAM roles específicas
  • Monitoramento Completo - CloudWatch com alertas e métricas
  • Backup Automatizado - Backup automático do banco de dados

Ambientes Suportados

Ambiente Finalidade Recursos Configuração
dev Desenvolvimento e testes Recursos mínimos (t3.micro) Single-AZ, sem NAT Gateway
prod Produção Recursos otimizados Multi-AZ, NAT Gateway, WAF

🏗️ Arquitetura da Solução

Componentes da Infraestrutura

🌐 VPC (Virtual Private Cloud)

Rede isolada com subnets públicas e privadas distribuídas em múltiplas AZs para alta disponibilidade.

⚖️ Application Load Balancer

Distribuição de tráfego com health checks e integração com WAF para proteção contra ataques.

🐳 ECS (Elastic Container Service)

Orquestração de containers com auto scaling baseado em CPU e integração com CloudWatch.

🗄️ RDS PostgreSQL

Banco de dados gerenciado com backup automático, criptografia e monitoramento de performance.

🔐 Security & IAM

Roles e políticas específicas, Security Groups restritivos e criptografia KMS.

📊 CloudWatch

Monitoramento completo com logs centralizados, métricas customizadas e alertas.

Fluxo de Dados

Internet → WAF → ALB → ECS Tasks → RDS PostgreSQL ↓ CloudWatch Logs & Metrics
⚠️ Importante: A aplicação roda exclusivamente no HCP Terraform Cloud. Não há configuração local de backend.

🚀 Deploy e Configuração

Pré-requisitos

  • Conta no HCP Terraform Cloud
  • Workspace configurado: SevenCloud_Challange
  • Credenciais AWS configuradas no HCP
  • Repositório ECR com a imagem da aplicação

Configuração do HCP Terraform Cloud

Variáveis de Ambiente Necessárias

Variável Tipo Descrição Exemplo
AWS_ACCESS_KEY_ID Sensitive Access Key da AWS AKIA...
AWS_SECRET_ACCESS_KEY Sensitive Secret Key da AWS ***
AWS_DEFAULT_REGION Normal Região AWS us-east-1

Variáveis do Terraform

Variável Valor Padrão Descrição
environment dev Ambiente (dev ou prod)
aws_region us-east-1 Região AWS
ecr_repository_url 194722426008.dkr.ecr.us-east-1.amazonaws.com/bia URL do repositório ECR
postgres_version 15.8 Versão do PostgreSQL

Processo de Deploy

  1. Commit do Código: Push para o repositório Git
  2. Trigger Automático: HCP Terraform detecta mudanças
  3. Plan: Terraform gera o plano de execução
  4. Review: Revisar mudanças no HCP Terraform
  5. Apply: Confirmar e aplicar mudanças
  6. Verificação: Validar recursos criados
✅ Deploy Bem-sucedido: Após o deploy, a aplicação estará disponível através do ALB endpoint.

⚙️ Gerenciamento da Infraestrutura

Operações Comuns

🔄 Atualizar a Aplicação

  1. Fazer push da nova imagem para o ECR
  2. Atualizar a variável ecr_repository_url se necessário
  3. Executar terraform apply no HCP
  4. ECS fará o rolling update automaticamente

📈 Escalar a Aplicação

Para alterar os limites de scaling, edite o arquivo locals.tf:

# Em locals.tf, seção env_config task_min_capacity = 2 # Mínimo de tasks task_max_capacity = 20 # Máximo de tasks task_desired_capacity = 3 # Capacidade desejada inicial

🔍 Monitoramento

Acesse o CloudWatch para:

  • Visualizar logs da aplicação em /ecs/bia
  • Monitorar métricas de CPU, memória e rede
  • Configurar alertas personalizados

🔥 Destruir a Infraestrutura

⚠️ ATENÇÃO: Esta operação é irreversível e removerá todos os recursos!

Via Interface Web (Recomendado)

  1. Acesse: HCP Terraform Workspace
  2. Vá em Settings → Destruction and Deletion
  3. Clique em "Queue destroy plan"
  4. Revise os recursos que serão removidos
  5. Confirme com "Confirm & Apply"

Via CLI

terraform destroy # Confirme digitando 'yes' quando solicitado

🔧 Troubleshooting

Problemas Comuns

❌ Deploy Falha no HCP Terraform

Sintomas: Erro durante terraform apply

Soluções:

  • Verificar se as credenciais AWS estão corretas
  • Confirmar se a região AWS está disponível
  • Verificar limites de recursos na conta AWS
  • Revisar logs detalhados no HCP Terraform

🐳 ECS Tasks não iniciam

Sintomas: Tasks ficam em estado PENDING ou STOPPED

Soluções:

  • Verificar se a imagem ECR existe e está acessível
  • Confirmar se as IAM roles têm permissões corretas
  • Verificar recursos disponíveis no cluster (CPU/memória)
  • Analisar logs do ECS Agent no CloudWatch

🗄️ Conexão com RDS falha

Sintomas: Aplicação não consegue conectar ao banco

Soluções:

  • Verificar Security Groups do RDS
  • Confirmar se o RDS está na subnet correta
  • Validar credenciais no AWS Secrets Manager
  • Testar conectividade de rede

⚖️ ALB retorna 503/504

Sintomas: Erro de gateway no load balancer

Soluções:

  • Verificar health check do target group
  • Confirmar se as tasks estão healthy
  • Validar configuração de portas
  • Analisar logs do ALB

Comandos Úteis para Debug

# Verificar estado do Terraform terraform show # Ver outputs terraform output # Validar configuração terraform validate # Planejar mudanças terraform plan

🔧 Como Modificar os Módulos

💡 Dica: Sempre teste mudanças no ambiente dev antes de aplicar em prod.

Guia Rápido de Modificações

🌐 Modificar Configurações de Rede (VPC)

Arquivo: modules/vpc/main.tf

# Para alterar CIDR da VPC, edite locals.tf: env_config = { dev = { vpc_cidr = "10.0.0.0/16" # Altere aqui availability_zones = 3 # Número de AZs } }

Modificações Comuns:

  • Adicionar mais subnets: Aumente availability_zones
  • Alterar CIDR: Modifique vpc_cidr
  • Habilitar NAT Gateway: Mude create_nat_gateway = true

🐳 Modificar Configurações do ECS

Arquivo: locals.tf (seção env_config)

# Alterar recursos do container container_cpu = 2048 # CPU units (1024 = 1 vCPU) container_memory = 512 # Memória em MB # Alterar auto scaling task_min_capacity = 1 # Mínimo de tasks task_max_capacity = 10 # Máximo de tasks task_desired_capacity = 2 # Capacidade inicial # Alterar thresholds de scaling cpu_scale_target = 70.0 # % CPU para trigger scaling

🗄️ Modificar Configurações do RDS

Arquivo: locals.tf

# Alterar classe da instância rds_instance_class = "db.t3.small" # Upgrade de performance # Alterar backup backup_retention_period = 14 # Dias de retenção # Habilitar Multi-AZ multi_az = true # Alta disponibilidade

⚖️ Modificar Configurações do ALB

Arquivo: modules/alb/main.tf

# Alterar health check health_check { enabled = true healthy_threshold = 2 # Checks para considerar healthy unhealthy_threshold = 3 # Checks para considerar unhealthy timeout = 5 # Timeout em segundos interval = 30 # Intervalo entre checks path = "/health" # Endpoint de health check matcher = "200" # HTTP status esperado }

Processo de Modificação

  1. Backup: Sempre faça backup do estado atual
  2. Edição: Modifique os arquivos necessários
  3. Validação: Execute terraform validate
  4. Plan: Execute terraform plan para revisar
  5. Apply: Execute terraform apply
  6. Verificação: Confirme se tudo está funcionando

Variáveis Importantes para Modificação

Variável Localização Impacto Exemplo
environment variables.tf Altera todo o comportamento dev, prod
container_cpu locals.tf Performance da aplicação 1024, 2048, 4096
rds_instance_class locals.tf Performance do banco db.t3.micro, db.t3.small
task_max_capacity locals.tf Escalabilidade máxima 5, 10, 20
⚠️ Cuidados Importantes:
• Mudanças em recursos críticos (RDS, VPC) podem causar downtime
• Sempre teste em ambiente de desenvolvimento primeiro
• Faça backup do banco antes de mudanças no RDS
• Monitore a aplicação após mudanças de performance

Exemplos Práticos de Modificação

Exemplo 1: Aumentar Performance da Aplicação

# Em locals.tf, seção dev ou prod: container_cpu = 4096 # Dobrar CPU container_memory = 1024 # Dobrar memória task_desired_capacity = 3 # Mais tasks iniciais

Exemplo 2: Melhorar Segurança

# Em modules/security-groups/main.tf: # Restringir acesso SSH apenas para IPs específicos ingress { from_port = 22 to_port = 22 protocol = "tcp" cidr_blocks = ["203.0.113.0/24"] # Seu IP específico }

Exemplo 3: Configurar Alertas Customizados

# Em modules/cloudwatch/main.tf: resource "aws_cloudwatch_metric_alarm" "high_memory" { alarm_name = "bia-high-memory-${var.environment}" comparison_operator = "GreaterThanThreshold" evaluation_periods = "2" metric_name = "MemoryUtilization" namespace = "AWS/ECS" period = "300" statistic = "Average" threshold = "80" alarm_description = "This metric monitors memory utilization" }
